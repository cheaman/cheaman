## 처리 흐름
넣기(base64 → 3_자료) → 종류 가르기 → 도면이면 숫자 · 겹침 · SVG → 봐주세요_NNN.md → claude -p (있으면) → 파악한것_NNN.json → 되받아 검사 → 자료.json 이해 → 화면 3초마다 → ○ → 규칙.json → 올리기 → 규칙글_13장.md + 시험기록.json

## 이미 밟은 함정
| 증상 | 까닭 → 해법 |
|---|---|
| 두 도면을 넣으니 한쪽 숫자가 사라짐 | 두 스레드가 자료.json 을 동시에 읽고 써서 한쪽이 덮임 → 창고에 RLock (규칙.py `_잠금`) |
| AI 답을 못 읽음 「Extra data」 | 답 글에 JSON 뒤 말이 붙음 → `JSON뽑기` 가 첫 { 부터 raw_decode |
| 시험에서 파일 고르기가 비어 옴 | 이 샌드박스의 Playwright 는 경로를 못 넘김 → buffer 로 넘김 (PC 에선 상관없음) |
| bash 에서 한글 변수가 안 됨 | 시험 .sh 변수는 영문 |
| 묵은 서버가 안 꺼져 새 서버가 자리를 못 잡음 | `pkill -f "[8]949 --"` (제 셸이 안 걸리게 대괄호) |
| ezdxf 의 LEADER vertices 가 tuple | Vec2 로 감쌈 |
| 두 도면을 동시에 그리면 「Glyph … coordinates」 로 한쪽 처리가 통째로 멈춤 | ezdxf 글꼴 부품이 동시 실행에 약함 → SVG 는 `그림잠금` 으로 하나씩 · 숫자는 그림보다 먼저 저장 · 그림 실패는 못읽음 한 줄 |
| 시험이 AI 답을 안 기다리고 지나감 | page.waitForFunction 에 async 함수를 주면 약속을 바로 참으로 봄 → 노드 쪽 되묻기 |
| 자료 넷을 한꺼번에 넣으니 셋이 「150초 안에 답 없음」 | claude -p 넷이 동시에 돌아 느려짐 → AI다리 `줄` 로 하나씩 (앞에 n건 · 끝 예정 = 90초 × 건수) · 180초 |
| AI 가 「파일 저장 허가가 안 나 못 했음」 | 봐주세요에 「파악한것.json 에 쓰라」 가 적혀 있어 AI 가 파일을 쓰려 함 → claude 길이면 「그대로 출력」 · 규칙 7 「파일 쓰지 않음」 |
| 시험 .sh 의 pkill 이 제 셸을 죽임 (exit 144) | 호출한 셸 명령줄에 같은 글이 있으면 pkill -f 가 그것도 잡음 → `[8]951` 꼴 · 시험은 따로 부름 |
